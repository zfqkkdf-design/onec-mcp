# Шлюз від мовної моделі до 1С

Це не бот у групі і не Telegram. Сервіс на Go стоїть між клієнтом MCP і HTTP-сервісом 1С. Модель викликає інструмент, шлюз питає 1С і повертає те, що віддала 1С.

Інструмент `stock_balance` запитує залишки товарів на дату. Кількість приходить зі звіту 1С. Модель залишок не рахує і не підставляє число, якого не було у відповіді. Поруч є наявність за період, товар у дорозі і резерв, якщо профіль бази їх віддав. Який набір відкритий, вирішує профіль 1С і область доступу токена, а не текст моделі.

Окрім залишків шлюз шукає в 1С контрагентів, склади, товари, канали продажів, каси і статті. Окремі інструменти питають продажі, гроші в касі, рух грошей, дебіторку, кредиторку і закупівлі. У кожного інструмента своя область доступу. Без неї виклик відхиляється, навіть якщо модель просить звіт.

Кілька баз 1С висять на одному шлюзі, кожна за своїм шляхом. Бази додаються в `/admin` і зберігаються в SQLite. Токен, випущений для однієї бази, на іншій не приймається. Порожній запуск віддає лише `/health` і адмінку, доки базу не додано.

## Стек

- Go 1.23+
- MCP, JSON-RPC 2.0
- HTTP-сервіс 1С
- OAuth 2.0 для клієнтів моделі
- SQLite

## Запуск

```bash
go run ./cmd/server
```

Перевірка: `GET /health` на порту `8088`. Точка для моделі: `POST /{slug}/mcp`. Конфіг тримає лише те, що потрібно для старту і входу в `/admin`. Адреси баз 1С у файлі конфігурації немає: вони живуть у SQLite.

Технічні контракти ендпоінтів, OAuth і очікуваний бік 1С лишаються в каталозі `docs/`.
